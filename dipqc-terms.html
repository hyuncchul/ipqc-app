공개 앱을 사용하는 방법과 데이터 관리 범위를 안내합니다.

접속과 팀 권한

현재 검사 기록은 기기별로 저장되며 팀 공통 검사 기록·사진 연결은 아직 활성화되지 않았습니다. 공개 품번 목록은 로그인 없이 조회할 수 있고 Google 로그인 후 추가·수정할 수 있습니다. 팀 검사 기록과 공통 사진은 별도 팀 저장 기능이 설정된 경우 승인된 구성원만 사용합니다. 하나의 Google 로그인 후 팀 권한에서 품질팀 또는 생산팀을 신청하세요. 관리자는 신청을 승인하거나 이메일로 담당자를 등록합니다. 앱 주소를 공유하는 것만으로 비공개 검사 기록 접근 권한이 생기지 않습니다.

설비 선택 → QR 카드 번호 → 카드 발행일

기본 입력 방법에서 설비 현황 계정으로 로그인하고 설비를 선택하면 hyuncchul.github.io/ipqc-app/production.html의 현재 생산 정보를 불러옵니다. 이 앱은 해당 서비스에서 정보를 조회하며 생산 정보는 수정하지 않습니다. 선택한 품번·제품 설명·금형·원료·오더 등 설비 정보를 확인하고 가운데 QR로 Card No를 읽은 뒤 실제 카드 발행일만 직접 입력하세요. 생산 사이트의 원본 카드 날짜는 참고 정보로 별도 보관됩니다. 등록 시 조회한 설비 정보를 검사 기록에 보관하며, 설비 정보가 변경되면 다시 선택하고 카드 내용을 확인해야 합니다. 계정은 해당 사이트와 같지만 이 앱에서 별도 로그인해야 하며 비밀번호는 저장하지 않습니다. 기존 방식은 ‘기존 바코드·사진 입력’을 선택해 QR·품번 바코드 또는 카드 사진 인식으로 사용할 수 있습니다. i630 PDA는 키보드 입력 모드로 사용하고 사진 인식 결과는 실제 카드와 비교해 확인하세요.

품질 등록 → 생산 작업 → 품질 재확인

품질팀은 제품·카드 정보와 불량 수량을 확인하고 FOL/EOL/OQC 및 불량 내용을 등록합니다. 등록일은 스캔일을 사용하며 등록 후 등록 이력으로 이동합니다. 생산팀은 목록 오른쪽에서 검사 방법을 재검사, Sorting, Scrap, 기타 중 선택합니다. 기타는 검사 방법을 직접 입력합니다. 생산 담당자가 전량 처리 수량·일자·결과와 필요한 증명 사진을 입력하고 재검사 진행 완료를 누르면 품질 재검사 탭으로 이동합니다. Scrap도 품질 확인을 거칩니다. 품질팀은 생산 결과와 불량 전후 사진을 확인하고 재검사합니다. 문제가 없으면 Pass로 처리 완료 목록에 최종 결과를 표시하고, NG이면 같은 등록 번호로 등록 이력에 돌아가 생산팀이 검사 방법을 선택해 동일 절차를 다시 진행합니다. 기존 불량과 이전 회차는 보존됩니다. 앱은 실제 제품을 폐기하지 않으며 기존 Pass, Waive, MRB, NG, Scrap, 기타 결과 기록을 보존합니다.

제품 사진과 Google 로그인

팀 사진 저장이 설정되어 있으면 기존 Google 로그인으로 제품·불량·처리 후 사진을 추가하고 전후 비교할 수 있습니다. 새 사진은 비공개 공통 Google 저장소를 사용하므로 별도의 Drive 연결이 필요하지 않습니다. 사진 저장 설정이나 권한 오류가 있으면 화면 안내를 확인해 주세요. 카드 문자 인식용 사진은 자동으로 증명 사진에 추가되지 않습니다. 기존 Drive 사진에는 원래 파일 권한이 적용됩니다.

공유·가져오기와 Excel

팀 공통 저장 기능이 활성화되면 승인된 구성원의 온라인 기기는 공유 검사 기록의 변경을 받습니다. 작업은 서버 저장 확인 후 반영되며 다른 담당자의 변경과 충돌하면 최신 기록을 다시 열어 주세요. 기존 기기 기록은 자동 공유되지 않고 관리자가 가져오기를 직접 실행해야 합니다. 새 등록 번호의 기록만 가져오며 기존 공유 기록을 덮어쓰지 않습니다. 목록 Excel에는 최종 처리 결과와 별도 회차 이력이 포함됩니다. 공유 품번 수정은 과거 검사 기록의 제품 정보를 바꾸지 않습니다.

운영 문의

앱은 데이터 입력·조회·내보내기를 돕습니다. 공정 기준, 판정 근거, 보관·공유 방식은 사용자가 실제 업무에 맞게 확인하세요. 사용 방법과 오류는 아래 공개 GitHub Issues에 문의할 수 있습니다.

Usage information

Updated: 2026-10-21

How to use the public app and manage your data.

Access and team permissions

Inspection records are currently stored per device; shared team inspection records and photos are not yet enabled. The public parts list can be read without sign-in and edited after Google sign-in. Team inspection records and shared photos require configured team storage and approved membership. After one Google sign-in, request a quality or production role in team access. Administrators approve requests or register staff by email. Sharing the app URL alone does not grant access to private inspection records.

Select equipment → QR card number → card issue date

In the default input mode, sign in with your equipment status account and select equipment to load current production data from hyuncchul.github.io/ipqc-app/production.html. This app reads that service without modifying production data. Check its part number, description, mold, material, order, and other equipment details, scan the center QR for Card No, then manually enter the actual card issue date. The source card date is kept separately for reference. The retrieved equipment details are saved with the inspection record; if they change, select the equipment again and check the card. Use the same account as the source site, but sign in separately in this app; passwords are not stored. Choose “Use barcode or card photo” to retain QR/part-barcode and card-photo recognition. Set i630 PDA to keyboard input mode and verify photo recognition against the actual card.

Quality registration → production work → quality review

Quality staff verify product/card details and defect quantity, select FOL/EOL/OQC, and record the defect. The scan date is used as the registration date, and the record moves to registration history. On the right of the list, production selects Reinspection, Sorting, Scrap, or Other; Other requires a manually entered method. Production enters the full processed quantity, date, results, and any evidence photos, then selects Complete reinspection to move the record to the Quality reinspection tab. Scrap also requires quality review. Quality checks production results and before/after photos, then reinspects. Pass places the final result in the completed list; NG returns the same record ID to registration history so production can select a method and repeat the process. The original defect and previous cycles are preserved. The app does not physically discard products and retains existing Pass, Waive, MRB, NG, Scrap, and Other decisions.

Product photos and Google sign-in

When team photo storage is configured, the same Google sign-in lets you add product, defect, and after-treatment photos and compare before/after. New photos use private shared Google storage, without a separate Drive connection. Follow the displayed guidance if storage configuration or permissions are unavailable. Card-text recognition photos are not automatically added as evidence. Existing Drive photos keep their original file permissions.

Sharing, imports, and Excel

When shared team storage is enabled, approved members’ online devices receive shared inspection changes. Work is applied after server acknowledgement; if another operator changes the record first, reopen the latest record. Existing device records are not automatically shared: an administrator must explicitly import them. Imports create only new record IDs and do not overwrite existing shared records. List exports include final outcomes and a separate cycle-history sheet. Changes to shared parts do not alter product details in previous inspection records.

Operational questions

The app assists with data entry, review, and export. Check process criteria, decision evidence, retention, and sharing practices against your actual workflow. Use the public GitHub Issues below for usage questions and errors.

使用說明

更新日期：2026-10-21

公開應用程式的使用方式與資料管理範圍。

存取與團隊權限

目前檢驗紀錄依裝置儲存，團隊共用檢驗紀錄與照片尚未啟用。公開料號可免登入查閱，Google 登入後可新增或修改。團隊檢驗紀錄及共用照片須先完成團隊儲存設定，並由核准成員使用。一次 Google 登入後，可在團隊權限中申請品質或生產職責。管理員審核申請或以電子郵件新增人員。分享應用程式網址本身不會授予非公開檢驗資料的存取權。

選擇設備 → QR 卡號 → 卡片發行日期

預設輸入方式為使用設備現況帳號登入並選擇設備，以載入 hyuncchul.github.io/ipqc-app/production.html 目前的生產資訊。此應用程式僅查詢該服務，不修改生產資料。請確認料號、產品說明、模具、原料、訂單及其他設備資訊，掃描中央 QR 碼讀取卡號，再手動輸入實際卡片發行日期。來源卡片日期會另外保留供參考。查詢到的設備資料會隨檢驗紀錄保存；資料變更時，須重新選擇設備並確認卡片。使用與來源網站相同的帳號，但需在此應用程式另外登入；不儲存密碼。選擇「使用條碼或卡片照片」可繼續使用 QR、料號條碼及卡片照片辨識。i630 PDA 請使用鍵盤輸入模式，照片辨識結果須與實際卡片比對。

品質登錄 → 生產作業 → 品質複查

品質人員確認產品、卡片及不良數量，選擇 FOL/EOL/OQC 並登錄不良內容。登錄日期使用掃描日，登錄後移至登錄紀錄。生產人員在清單右側選擇複驗、篩選、報廢或其他檢驗方式；選擇其他時須自行輸入方式。生產人員輸入全數處理數量、日期、結果及所需證明照片，再按完成複驗作業，紀錄即移至品質複驗頁籤。報廢亦須經品質確認。品質人員查看生產結果及處理前後照片並進行複驗。合格時將最終結果列入處理完成清單；不合格時以相同登錄編號退回登錄紀錄，由生產人員重新選擇檢驗方式並重複流程。原始不良與先前各輪歷程均會保留。應用程式不會實際銷毀產品，既有 Pass、Waive、MRB、NG、Scrap 與其他結果均會保留。

產品照片與 Google 登入

團隊照片儲存設定完成後，可用同一 Google 登入新增產品、不良與處理後照片並比較前後。新照片使用非公開 Google 共用儲存空間，無須另行連接 Drive。若設定或權限不足，請依畫面提示處理。卡片文字辨識照片不會自動新增為證明照片。既有 Drive 照片維持原檔案權限。

共用、匯入與 Excel

團隊共用儲存啟用後，核准成員的連線裝置會收到共用檢驗資料更新。

Hướng dẫn sử dụng

Cập nhật: 2026-10-21

Cách sử dụng ứng dụng công khai và quản lý dữ liệu.

Truy cập và quyền nhóm

Hiện hồ sơ kiểm tra được lưu riêng trên từng thiết bị; hồ sơ và ảnh kiểm tra dùng chung cho nhóm chưa được bật. Danh mục mã hàng công khai có thể xem không cần đăng nhập và chỉnh sửa sau khi đăng nhập Google. Hồ sơ kiểm tra và ảnh nhóm cần cấu hình lưu trữ nhóm cùng quyền thành viên được phê duyệt. Sau một lần đăng nhập Google, xin vai trò chất lượng hoặc sản xuất trong quyền nhóm. Quản trị viên duyệt đơn hoặc đăng ký người dùng bằng email. Chỉ chia sẻ URL ứng dụng không cấp quyền xem hồ sơ kiểm tra nội bộ.

Chọn thiết bị → số thẻ QR → ngày phát hành thẻ

Ở cách nhập mặc định, đăng nhập bằng tài khoản tình trạng thiết bị rồi chọn thiết bị để tải dữ liệu sản xuất hiện tại từ hyuncchul.github.io/ipqc-app/production.html. Ứng dụng chỉ đọc, không sửa dữ liệu sản xuất của dịch vụ. Kiểm tra mã hàng, mô tả, khuôn, nguyên liệu, số lệnh và thông tin thiết bị khác; quét QR ở giữa để đọc số thẻ, rồi nhập thủ công ngày phát hành trên thẻ thực tế. Ngày thẻ nguồn được giữ riêng để tham khảo. Thông tin thiết bị đã tra cứu được lưu cùng hồ sơ kiểm tra; nếu dữ liệu thay đổi, phải chọn lại thiết bị và kiểm tra thẻ. Dùng cùng tài khoản với trang nguồn nhưng đăng nhập riêng trong ứng dụng này; mật khẩu không được lưu. Chọn “Dùng mã vạch hoặc ảnh thẻ” để dùng lại QR, mã vạch mã hàng và nhận dạng ảnh thẻ. Đặt i630 PDA ở chế độ bàn phím và đối chiếu kết quả ảnh với thẻ thực tế.

Chất lượng ghi nhận → sản xuất xử lý → chất lượng kiểm tra lại

Chất lượng xác nhận thông tin sản phẩm, thẻ và số lượng lỗi, chọn FOL/EOL/OQC và ghi nhận nội dung lỗi. Ngày quét là ngày ghi nhận; sau khi lưu, bản ghi chuyển đến lịch sử ghi nhận. Ở bên phải danh sách, sản xuất chọn Kiểm tra lại, Sàng lọc, Loại bỏ hoặc Khác; Khác yêu cầu nhập trực tiếp phương pháp. Sản xuất nhập toàn bộ số lượng đã xử lý, ngày, kết quả và ảnh minh chứng cần thiết, rồi chọn Hoàn tất kiểm tra lại để chuyển bản ghi sang tab Kiểm tra lại chất lượng. Loại bỏ cũng phải được chất lượng xác nhận. Chất lượng xem kết quả sản xuất và ảnh trước/sau rồi kiểm tra lại. Pass đưa kết quả cuối vào danh sách hoàn tất; NG trả về lịch sử ghi nhận với cùng ID để sản xuất chọn phương pháp và thực hiện lại quy trình. Lỗi ban đầu và các vòng trước được giữ nguyên. Ứng dụng không trực tiếp hủy sản phẩm và giữ lại các kết quả Pass, Waive, MRB, NG, Scrap và Khác trước đây.

Ảnh sản phẩm và đăng nhập Google

Khi kho ảnh nhóm đã cấu hình, dùng cùng đăng nhập Google để thêm ảnh sản phẩm, lỗi và sau xử lý, rồi so sánh trước/sau. Ảnh mới dùng kho Google chung riêng tư, không cần kết nối Drive riêng. Nếu thiếu cấu hình hoặc quyền, làm theo thông báo trên màn hình. Ảnh nhận dạng chữ trên thẻ không tự thêm làm minh chứng. Ảnh Drive cũ giữ quyền của tệp gốc.

Chia sẻ, nhập dữ liệu và Excel

Khi lưu trữ nhóm được bật, thiết bị trực tuyến của thành viên được duyệt nhận các thay đổi hồ sơ dùng chung. Công việc chỉ có hiệu lực sau khi máy chủ xác nhận lưu; nếu người khác thay đổi trước, mở lại hồ sơ mới nhất. Hồ sơ cũ trên thiết bị không tự chia sẻ; quản trị viên phải chủ động nhập. Nhập chỉ tạo ID hồ sơ mới, không ghi đè hồ sơ chung đang có. Excel gồm kết quả cuối và trang lịch sử từng vòng riêng. Sửa mã hàng chung không đổi thông tin sản phẩm của hồ sơ kiểm tra trước đó.

Câu hỏi vận hành

Ứng dụng hỗ trợ nhập, xem và xuất dữ liệu. Hãy xác nhận tiêu chí công đoạn, căn cứ kết luận, cách lưu giữ và chia sẻ theo quy trình thực tế. Dùng GitHub Issues công khai bên dưới để hỏi cách dùng hoặc báo lỗi.

Panduan penggunaan

Diperbarui: 2026-10-21

Cara menggunakan aplikasi publik dan mengelola data Anda.

Akses dan izin tim

Catatan inspeksi saat ini disimpan per perangkat; catatan dan foto inspeksi bersama tim belum diaktifkan. Daftar komponen publik dapat dibaca tanpa login dan diedit setelah login Google. Catatan inspeksi tim dan foto bersama memerlukan konfigurasi penyimpanan tim serta keanggotaan yang disetujui. Setelah satu login Google, ajukan peran kualitas atau produksi melalui akses tim. Administrator menyetujui permintaan atau mendaftarkan petugas lewat email. Membagikan URL aplikasi saja tidak memberi akses ke catatan inspeksi privat.

Pilih peralatan → nomor kartu QR → tanggal penerbitan

Dalam mode input bawaan, masuk dengan akun status peralatan lalu pilih peralatan untuk memuat data produksi terkini dari hyuncchul.github.io/ipqc-app/production.html. Aplikasi hanya membaca layanan tersebut tanpa mengubah data produksi. Periksa nomor komponen, deskripsi, cetakan, bahan, order, dan rincian peralatan lainnya; pindai QR tengah untuk nomor kartu, lalu masukkan tanggal penerbitan pada kartu asli secara manual. Tanggal kartu sumber disimpan terpisah sebagai referensi. Rincian peralatan yang diambil disimpan bersama catatan inspeksi; jika data berubah, pilih ulang peralatan dan periksa kartu. Gunakan akun yang sama dengan situs sumber, tetapi masuk secara terpisah di aplikasi ini; kata sandi tidak disimpan. Pilih “Gunakan kode batang atau foto kartu” untuk tetap memakai QR, kode batang komponen, dan pengenalan foto kartu. Atur i630 PDA ke mode papan ketik dan cocokkan hasil pengenalan foto dengan kartu asli.

Pencatatan kualitas → pekerjaan produksi → pemeriksaan kualitas

Tim kualitas memeriksa detail produk, kartu, dan jumlah cacat, memilih FOL/EOL/OQC, lalu mencatat cacat. Tanggal pemindaian digunakan sebagai tanggal pencatatan, lalu catatan masuk ke riwayat pencatatan. Di sisi kanan daftar, produksi memilih Pemeriksaan ulang, Penyortiran, Afkir, atau Lainnya; Lainnya memerlukan metode yang diketik sendiri. Produksi memasukkan seluruh jumlah yang diproses, tanggal, hasil, dan foto bukti yang diperlukan, lalu memilih Selesaikan pemeriksaan ulang untuk memindahkan catatan ke tab Pemeriksaan ulang kualitas. Afkir juga memerlukan pemeriksaan kualitas. Tim kualitas meninjau hasil produksi dan foto sebelum/sesudah, lalu memeriksa ulang. Pass menampilkan hasil akhir dalam daftar selesai; NG mengembalikan ID catatan yang sama ke riwayat pencatatan agar produksi memilih metode dan mengulangi proses. Cacat awal dan siklus sebelumnya tetap disimpan. Aplikasi tidak membuang produk secara fisik dan tetap menyimpan hasil lama Pass, Waive, MRB, NG, Scrap, dan Lainnya.

Foto produk dan login Google

Jika penyimpanan foto tim dikonfigurasi, gunakan login Google yang sama untuk menambah foto produk, cacat, dan setelah penanganan serta membandingkan sebelum/sesudah. Foto baru memakai penyimpanan Google bersama privat, tanpa koneksi Drive terpisah. Ikuti petunjuk layar bila konfigurasi atau izin belum tersedia. Foto pengenalan teks kartu tidak otomatis ditambahkan sebagai bukti. Foto Drive lama tetap memakai izin berkas asli.

Berbagi, impor, dan Excel

Saat penyimpanan bersama tim diaktifkan, perangkat online anggota yang disetujui menerima perubahan catatan bersama. Pekerjaan berlaku setelah server mengonfirmasi penyimpanan; jika petugas lain lebih dahulu mengubahnya, buka kembali catatan terbaru. Catatan perangkat lama tidak otomatis dibagikan: administrator harus mengimpor secara tegas. Impor hanya membuat ID catatan baru dan tidak menimpa catatan bersama yang ada. Excel memuat hasil akhir dan lembar riwayat siklus terpisah. Perubahan komponen bersama tidak mengubah detail produk dalam catatan inspeksi sebelumnya.

PEAK Inspection에서 사용하는 데이터와 저장 위치를 안내합니다.

공유 품번과 비공개 팀 검사 기록

현재 검사 기록은 기기별로 저장되며 팀 공통 검사 기록·사진 연결은 아직 활성화되지 않았습니다. 기본 품번 905개와 추가·수정한 공유 품번은 누구나 조회할 수 있습니다. 공유 품번 문서에는 SAP PN, Description, Mold, 수정 시각과 수정자 UID가 저장됩니다. 팀 검사 기능이 설정된 경우 검사 기록은 Cloud Firestore에 저장되며 관리자가 승인한 구성원끼리 공유됩니다. 제품·카드 정보, 불량 내용·수량, 담당자, 처리 시각, 생산 작업 결과, 품질 판정과 회차 이력이 포함됩니다. 서버 감사 이력에는 변경 전후 기록, 작업자 UID와 서버 시각이 보관됩니다.

설비 생산 정보와 카드 입력

설비 선택 시 hyuncchul.github.io/ipqc-app/production.html의 생산 정보를 해당 서비스의 서버(ltc-equipment-monitor.pwjwx2rg6w.chatgpt.site)에서 로그인 후 읽어 옵니다. 이 앱은 생산 사이트의 데이터를 수정하지 않습니다. 로그인 정보는 해당 인증 서버로 전송되며 비밀번호는 저장하지 않습니다. 로그인 토큰은 현재 탭의 sessionStorage에만 보관합니다. 선택 당시 설비 정보와 조회 시각은 불량 등록 시 검사 기록에 복사되어 보관되며 공개 품번 목록이나 GitHub에 게시되지 않습니다. 수동 입력한 카드 발행일과 생산 사이트의 원본 카드 날짜는 별도로 보관합니다. QR과 기존 바코드·사진 입력의 인식은 브라우저에서 수행하며 인식용 영상·사진 자체를 업로드하지 않습니다. 별도로 추가한 증명 사진은 아래 저장 방식을 따릅니다.

Google 공통 사진 저장

팀 사진 저장 기능은 별도의 Firebase Storage 설정이 필요합니다. 설정이 완료되면 새 증명 사진은 Google 로그인으로 앱의 비공개 공통 저장소에 업로드되며, 승인된 팀 구성원이 조회할 수 있습니다. 사진 데이터와 파일 식별자·경로·크기 등의 메타데이터가 저장됩니다. 추가 Drive 연결이나 개인 Drive 폴더 지정은 필요하지 않습니다. 설정 또는 권한이 준비되지 않으면 업로드 오류를 표시하며 사진을 공개하지 않습니다. 기존 Drive 사진은 기존 파일의 접근 권한을 유지합니다.

Google 로그인과 팀 권한

Firebase Authentication은 하나의 Google 로그인에 필요한 계정 식별자, 이메일과 기본 프로필을 처리합니다. 팀 권한 신청에는 이메일, 표시 이름, 신청 업무와 신청 시각이 포함되며 관리자가 검토합니다. 승인 정보에는 이메일, 담당 역할, 승인자 UID와 승인 시각이 저장됩니다. 품질팀은 등록·재확인, 생산팀은 작업 결과 입력, 관리자는 접근 권한과 가져오기를 관리합니다. 새 팀 사진 저장에는 Drive OAuth 권한을 요청하지 않습니다. 웹에 포함된 Firebase 설정은 공개 연결 식별자이며 비밀번호가 아닙니다.

이용 목적과 외부 서비스

Google 서비스는 로그인, 품번 관리, 팀 검사 기록·감사 이력과 증명 사진의 저장·조회에 사용됩니다. 앱에는 광고·방문 분석 기능이 없으며 Google 데이터를 광고나 AI 모델 학습에 사용하지 않습니다. GitHub는 사이트를 제공하고 Google은 Firebase Authentication, Cloud Firestore와 설정된 Cloud Storage를 제공합니다. 각 서비스의 데이터 처리에는 해당 개인정보 정책이 적용됩니다.

기존 기기 자료와 백업

기존 브라우저의 검사 기록과 사진은 자동으로 팀 저장소에 전송하지 않습니다. 관리자가 명시적으로 실행한 가져오기만 공유 기록을 생성합니다. 브라우저에는 설정, 캐시와 사진 사본이 남을 수 있습니다. Excel 및 백업 파일에는 검사 정보, 처리 회차, 사진 데이터 또는 저장 참조가 포함될 수 있으므로 파일 보관과 전달 범위는 사용자가 관리합니다. 사진 경로나 파일만으로 전체 검사 이력을 복구할 수는 없습니다.

보관·삭제와 로그아웃

브라우저 사이트 데이터를 지우거나 로그아웃해도 공통 저장소의 품번, 검사 기록, 감사 이력과 사진은 삭제되지 않습니다. 팀 기록과 사진의 보관·삭제 및 접근 권한 변경은 관리자에게 요청해 주세요. 기존 Drive 파일은 해당 Drive 소유자가 별도로 관리합니다. Google 계정에서 앱 연결을 철회해도 이미 저장된 자료가 자동 삭제되지는 않습니다.

Privacy notice

Updated: 2026-10-15

How PEAK Inspection uses and stores data.

Public parts and private team inspection records

Inspection records are currently stored per device; shared team inspection records and photos are not yet enabled. The baseline of 905 parts and shared additions and edits are publicly readable. Part documents store SAP PN, Description, Mold, update time, and editor UID. When team inspection is configured, Cloud Firestore stores records shared among approved members: product and card details, defect descriptions and quantities, operators, timestamps, production results, quality decisions, and cycle history. Server audit events retain before/after records, actor UID, and server time.

Equipment production data and card input

After sign-in, equipment selection reads production data for hyuncchul.github.io/ipqc-app/production.html from its service backend (ltc-equipment-monitor.pwjwx2rg6w.chatgpt.site). This app does not modify the production site. Login credentials are sent to that authentication server; passwords are not stored. The login token is kept only in the current tab’s sessionStorage. The selected equipment data and retrieval time are copied into the inspection record when a defect is registered, and are not published to the public parts list or GitHub. The manually entered card issue date is kept separately from the source card date. QR recognition and the existing barcode/photo input run in the browser without uploading recognition video or photos. Separately added evidence photos follow the storage rules below.

Shared Google photo storage

Team photo storage requires a separate Firebase Storage configuration. Once configured, new evidence photos use Google sign-in to upload to the app’s private shared storage and can be viewed by approved team members. Photo data and metadata such as file identifiers, paths, and sizes are stored. No additional Drive connection or personal Drive folder is required. Missing configuration or permission produces an upload error; it does not make photos public. Existing Drive photos retain their existing access permissions.

Google sign-in and team access

Firebase Authentication handles account identifiers, email, and basic profile information for one Google sign-in. Access requests include email, display name, requested role, and request time for administrator review. Membership records contain email, role, approver UID, and approval time. Quality staff register and review defects; production staff submit work results; administrators manage access and imports. New team-photo storage does not request Drive OAuth permissions. Firebase configuration in the website contains public connection identifiers, not passwords.

Purpose and external services

Google services support sign-in, parts management, team inspection records, audit history, and evidence-photo storage and retrieval. The app has no advertising or visitor analytics and does not use Google data for advertising or AI training. GitHub serves the site; Google provides Firebase Authentication, Cloud Firestore, and configured Cloud Storage. Each provider’s privacy policy governs its service processing.

Existing device data and backups

Existing browser inspection records and photos are not automatically uploaded to the team store. Only an import explicitly initiated by an administrator creates shared records. Settings, caches, and photo copies may remain in the browser. Excel and backup files can contain inspection details, processing cycles, photo data, or storage references; you manage their retention and recipients. Photo paths or files alone cannot restore the complete inspection history.

Retention, deletion, and sign-out

Clearing browser data or signing out does not delete shared parts, inspection records, audit history, or photos. Ask the administrator about team-data retention, deletion, and access changes. Existing Drive files remain separately managed by their Drive owner. Revoking the app’s Google connection does not automatically delete stored data.

隱私權說明

更新日期：2026-10-15

說明 PEAK Inspection 如何使用及儲存資料。

公開料號與非公開團隊檢驗紀錄

目前檢驗紀錄依裝置儲存，團隊共用檢驗紀錄與照片尚未啟用。基本的 905 個料號及後續新增、修改的共用料號可公開查閱。料號文件儲存 SAP PN、Description、Mold、修改時間及修改者 UID。啟用團隊檢驗設定後，Cloud Firestore 儲存經管理員核准之成員共用的產品與卡片資料、不良內容與數量、負責人、處理時間、生產結果、品質判定及各輪處理歷程。伺服器稽核事件保留變更前後紀錄、操作者 UID 與伺服器時間。

設備生產資訊與卡片輸入

選擇設備後，登入並透過 hyuncchul.github.io/ipqc-app/production.html 的服務後端（ltc-equipment-monitor.pwjwx2rg6w.chatgpt.site）讀取生產資訊。此應用程式不會修改生產網站的資料。登入資料會傳送至該驗證伺服器，不儲存密碼；登入權杖僅保存在目前分頁的 sessionStorage。登錄不良時，會將所選設備資料與查詢時間複製到檢驗紀錄中，不會發布至公開料號清單或 GitHub。手動輸入的卡片發行日期與來源卡片日期分開保留。QR 碼及既有條碼、照片輸入的辨識在瀏覽器中執行，不上傳辨識用影像或照片。另行新增的證明照片依下列方式儲存。

Google 共用照片儲存

團隊照片功能需要另行設定 Firebase Storage。完成設定後，新證明照片透過 Google 登入上傳至應用程式的非公開共用儲存空間，經核准的團隊成員可查閱。儲存內容包含照片及檔案識別碼、路徑、大小等中繼資料。無須另外連接 Drive 或指定個人 Drive 資料夾。若設定或權限不足會顯示上傳錯誤，不會將照片公開。既有 Drive 照片維持原有存取權限。

Google 登入與團隊權限

Firebase Authentication 處理單一 Google 登入所需的帳戶識別碼、電子郵件及基本個人資料。權限申請包含電子郵件、顯示名稱、申請職責及時間，供管理員審查。成員資料包含電子郵件、角色、核准者 UID 及時間。品質人員負責登錄與複查，生產人員輸入作業結果，管理員管理權限與匯入。新團隊照片儲存不要求 Drive OAuth 權限。網站中的 Firebase 設定是公開連線識別資訊，不是密碼。

用途與外部服務

Google 服務用於登入、料號管理、團隊檢驗紀錄、稽核歷程及證明照片儲存與查閱。應用程式沒有廣告或訪客分析，也不將 Google 資料用於廣告或 AI 訓練。GitHub 提供網站，Google 提供 Firebase Authentication、Cloud Firestore 及已設定的 Cloud Storage。各服務的資料處理適用其隱私權政策。

既有裝置資料與備份

既有瀏覽器檢驗紀錄及照片不會自動上傳至團隊儲存空間。只有管理員明確執行匯入，才會建立共用紀錄。設定、快取及照片副本可能仍保留在瀏覽器。Excel 與備份可能包含檢驗資料、處理輪次、照片資料或儲存參照；請管理其保存及傳送對象。僅靠照片路徑或檔案無法還原完整檢驗歷程。

保存、刪除與登出

清除瀏覽器資料或登出不會刪除共用料號、檢驗紀錄、稽核歷程或照片。團隊資料的保存、刪除及權限變更請洽管理員。既有 Drive 檔案由原 Drive 擁有者另行管理。撤銷 Google 帳戶的應用程式連線不會自動刪除已儲存資料。

Thông báo quyền riêng tư

Cập nhật: 2026-10-15

Cách PEAK Inspection sử dụng và lưu trữ dữ liệu.

Mã hàng công khai và hồ sơ kiểm tra nội bộ

Hiện hồ sơ kiểm tra được lưu riêng trên từng thiết bị; hồ sơ và ảnh kiểm tra dùng chung cho nhóm chưa được bật. 905 mã hàng gốc và các mục được thêm hoặc sửa dùng chung đều có thể xem công khai. Tài liệu mã hàng lưu SAP PN, Description, Mold, thời gian sửa và UID người sửa. Khi cấu hình kiểm tra nhóm được bật, Cloud Firestore lưu hồ sơ cho thành viên đã được phê duyệt: thông tin sản phẩm và thẻ, lỗi và số lượng, người phụ trách, thời gian, kết quả sản xuất, kết luận chất lượng và lịch sử từng vòng. Nhật ký máy chủ lưu hồ sơ trước/sau thay đổi, UID người thao tác và thời gian máy chủ.

Dữ liệu sản xuất của thiết bị và nhập thẻ

Sau khi đăng nhập, việc chọn thiết bị đọc dữ liệu sản xuất của hyuncchul.github.io/ipqc-app/production.html từ máy chủ dịch vụ (ltc-equipment-monitor.pwjwx2rg6w.chatgpt.site). Ứng dụng không sửa dữ liệu trên trang sản xuất. Thông tin đăng nhập được gửi tới máy chủ xác thực đó; mật khẩu không được lưu. Mã phiên đăng nhập chỉ nằm trong sessionStorage của tab hiện tại. Khi ghi nhận lỗi, dữ liệu thiết bị đã chọn và thời điểm tra cứu được sao chép vào hồ sơ kiểm tra, không công bố trong danh mục mã hàng hoặc GitHub. Ngày phát hành thẻ nhập thủ công được lưu riêng với ngày thẻ nguồn. Nhận dạng QR và cách nhập mã vạch/ảnh hiện có chạy trong trình duyệt, không tải lên video hoặc ảnh dùng để nhận dạng. Ảnh minh chứng thêm riêng tuân theo cách lưu bên dưới.

Lưu ảnh chung trên Google

Ảnh nhóm cần cấu hình Firebase Storage riêng. Khi đã cấu hình, ảnh minh chứng mới được tải lên kho chung riêng tư của ứng dụng bằng đăng nhập Google và thành viên đã được phê duyệt có thể xem. Dữ liệu ảnh và siêu dữ liệu như mã tệp, đường dẫn và kích thước được lưu. Không cần kết nối Drive riêng hoặc chọn thư mục Drive cá nhân. Nếu thiếu cấu hình hoặc quyền, ứng dụng báo lỗi tải lên và không công khai ảnh. Ảnh Drive cũ giữ nguyên quyền truy cập trước đó.

Đăng nhập Google và quyền nhóm

Firebase Authentication xử lý mã tài khoản, email và hồ sơ cơ bản cho một lần đăng nhập Google. Đơn xin quyền gồm email, tên hiển thị, vai trò đề nghị và thời gian để quản trị viên xét duyệt. Hồ sơ thành viên lưu email, vai trò, UID người duyệt và thời gian duyệt. Bộ phận chất lượng ghi nhận và kiểm tra lại; sản xuất nhập kết quả công việc; quản trị viên quản lý quyền và nhập dữ liệu. Lưu ảnh nhóm mới không yêu cầu quyền Drive OAuth. Cấu hình Firebase trên trang là thông tin kết nối công khai, không phải mật khẩu.

Mục đích và dịch vụ bên ngoài

Dịch vụ Google phục vụ đăng nhập, quản lý mã hàng, hồ sơ kiểm tra nhóm, nhật ký và lưu/xem ảnh minh chứng. Ứng dụng không có quảng cáo hay phân tích khách truy cập, không dùng dữ liệu Google cho quảng cáo hoặc huấn luyện AI. GitHub cung cấp trang web; Google cung cấp Firebase Authentication, Cloud Firestore và Cloud Storage đã cấu hình. Chính sách riêng tư của từng bên áp dụng cho việc xử lý của họ.

Dữ liệu cũ trên thiết bị và sao lưu

Hồ sơ và ảnh đang có trong trình duyệt không tự động tải lên kho nhóm. Chỉ thao tác nhập do quản trị viên chủ động thực hiện mới tạo hồ sơ chung. Cài đặt, bộ nhớ đệm và bản sao ảnh có thể còn trong trình duyệt. Excel và bản sao lưu có thể chứa thông tin kiểm tra, các vòng xử lý, dữ liệu ảnh hoặc tham chiếu lưu trữ; bạn quản lý việc giữ và chuyển các tệp này. Chỉ đường dẫn hoặc tệp ảnh không thể khôi phục toàn bộ lịch sử kiểm tra.

Lưu giữ, xóa và đăng xuất

Xóa dữ liệu trình duyệt hoặc đăng xuất không xóa mã hàng, hồ sơ kiểm tra, nhật ký hay ảnh dùng chung. Hãy liên hệ quản trị viên để quản lý lưu giữ, xóa hoặc thay đổi quyền dữ liệu nhóm. Pemberitahuan privasi

Diperbarui: 2026-10-15

Cara PEAK Inspection menggunakan dan menyimpan data.

Komponen publik dan catatan inspeksi tim privat

Catatan inspeksi saat ini disimpan per perangkat; catatan dan foto inspeksi bersama tim belum diaktifkan. 905 komponen awal serta penambahan dan perubahan bersama dapat dibaca publik. Dokumen komponen menyimpan SAP PN, Description, Mold, waktu perubahan, dan UID pengedit. Jika inspeksi tim dikonfigurasi, Cloud Firestore menyimpan catatan untuk anggota yang disetujui: detail produk dan kartu, cacat dan jumlah, petugas, waktu, hasil produksi, keputusan kualitas, dan riwayat setiap siklus. Audit server menyimpan catatan sebelum/sesudah perubahan, UID pelaku, dan waktu server.

Data produksi peralatan dan input kartu

Setelah masuk, pemilihan peralatan membaca data produksi untuk hyuncchul.github.io/ipqc-app/production.html dari server layanannya (ltc-equipment-monitor.pwjwx2rg6w.chatgpt.site). Aplikasi ini tidak mengubah data situs produksi. Kredensial dikirim ke server autentikasi tersebut; kata sandi tidak disimpan. Token masuk hanya disimpan dalam sessionStorage tab saat ini. Saat cacat dicatat, data peralatan yang dipilih dan waktu pengambilan disalin ke catatan inspeksi, tidak dipublikasikan ke daftar komponen atau GitHub. Tanggal penerbitan kartu yang dimasukkan manual disimpan terpisah dari tanggal kartu sumber. Pengenalan QR dan input kode batang/foto yang sudah ada dijalankan di browser tanpa mengunggah video atau foto pengenalan. Foto bukti yang ditambahkan terpisah mengikuti aturan penyimpanan di bawah.

Penyimpanan foto Google bersama

Foto tim memerlukan konfigurasi Firebase Storage terpisah. Setelah dikonfigurasi, foto bukti baru diunggah menggunakan login Google ke penyimpanan bersama privat aplikasi dan dapat dilihat anggota tim yang disetujui. Data foto dan metadata seperti ID, jalur, dan ukuran berkas disimpan. Tidak perlu koneksi Drive tambahan atau folder Drive pribadi. Konfigurasi atau izin yang belum tersedia menghasilkan kesalahan unggah, bukan foto publik. Foto Drive lama tetap menggunakan izin akses sebelumnya.

Login Google dan akses tim

Firebase Authentication memproses ID akun, email, dan profil dasar untuk satu login Google. Permintaan akses berisi email, nama tampilan, peran yang diminta, dan waktu untuk ditinjau administrator. Data keanggotaan menyimpan email, peran, UID pemberi persetujuan, dan waktunya. Tim kualitas mencatat dan memeriksa ulang; produksi memasukkan hasil pekerjaan; administrator mengatur akses dan impor. Foto tim baru tidak meminta izin Drive OAuth. Konfigurasi Firebase di situs adalah pengenal koneksi publik, bukan kata sandi.

Tujuan dan layanan eksternal

Layanan Google mendukung login, pengelolaan komponen, catatan inspeksi tim, audit, serta penyimpanan dan pembacaan foto bukti. Aplikasi tidak memiliki iklan atau analitik pengunjung dan tidak menggunakan data Google untuk iklan atau pelatihan AI. GitHub menyediakan situs; Google menyediakan Firebase Authentication, Cloud Firestore, dan Cloud Storage yang dikonfigurasi. Kebijakan privasi masing-masing penyedia berlaku untuk pemrosesan layanannya.

Data perangkat lama dan cadangan

Catatan inspeksi serta foto lama di browser tidak otomatis diunggah ke penyimpanan tim. Hanya impor yang dimulai secara tegas oleh administrator yang membuat catatan bersama. Pengaturan, cache, dan salinan foto dapat tetap berada di browser. Excel dan cadangan dapat memuat detail inspeksi, siklus penanganan, data foto, atau referensi penyimpanan; Anda mengatur penyimpanan dan penerimanya. Jalur atau berkas foto saja tidak dapat memulihkan seluruh riwayat inspeksi.

Retensi, penghapusan, dan logout

Menghapus data browser atau logout tidak menghapus komponen, catatan inspeksi, audit, atau foto bersama. Hubungi administrator untuk retensi, penghapusan, dan perubahan akses data tim. Berkas Drive lama tetap dikelola terpisah oleh pemilik Drive. Mencabut koneksi aplikasi di akun Google tidak otomatis menghapus data tersimpan.
